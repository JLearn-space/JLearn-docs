# Карта курса Git

Курс для тех, кто прошёл курсы HTML, CSS и JavaScript JLearn (курс jQuery желателен, но не обязателен). Ученик раньше не работал с терминалом и Git. В задании урока N используются только понятия из уроков 1–N. Версия - **Git 2.56** (осень 2026); там, где это важно, упоминается Git 3.0 (запланирован на весну 2027).

| Урок | Новые понятия | Задание в IDE | Опирается на |
| --- | --- | --- | --- |
| 1. Знакомство с Git и терминалом | Контроль версий; Git и GitHub - разница; установка Git; терминал: `pwd`, `ls`, `cd`, `mkdir`, `echo "..." > файл`, `cat`; `git --version`; `git config --global` (`user.name`, `user.email`, `init.defaultBranch`); `git init` и папка `.git`; `git status` | Настроить Git, создать папку проекта и репозиторий, первый файл | Курс HTML |
| 2. Первый коммит | Три зоны: рабочая папка, индекс, репозиторий; жизненный цикл файла; `git add` (файл, `.`); `git status -s`; `git commit -m`; хорошие сообщения коммитов; `git commit -am`; `>>` - дописать в файл; `cat > файл << 'EOF'` | Четыре коммита в проекте-портфолио: по одному файлу, затем `commit -am` | 1 |
| 3. История и изменения | `git log` (`--oneline`, `-n`, `--stat`, `-p`); `git show`; `git diff` и `git diff --staged`; хеш коммита; `HEAD`, `HEAD~1`; `git show HEAD~2:файл`; SHA-1 и SHA-256 в Git 3.0 | Найти в истории старую версию файла и вернуть её текст в новом коммите | 1–2 |
| 4. Отмена изменений | `git restore`, `git restore --staged`; `git commit --amend`; `git revert`; `git reset --soft / --mixed / --hard`; `git reflog`; правило: не переписывать опубликованную историю | Исправить четыре ошибки в репозитории подходящими командами | 1–3 |
| 5. Игнорирование файлов и порядок в проекте | `.gitignore`: шаблоны, `*`, `папка/`, `!`; что не хранить в Git (секреты, `node_modules`, сборки); `git rm --cached`; `git rm`, `git mv`; `README.md`; пустые папки и `.gitkeep` | Настроить `.gitignore` и убрать из истории отслеживания файл с секретом | 1–4 |

| 7. Слияние и конфликты | `git merge`: перемотка вперёд и коммит слияния; `--no-ff`; конфликт и его маркеры; разрешение конфликта; `git merge --abort`; удаление влитых веток | Влить две ветки, одна с конфликтом | 1–6 |
| 8. GitHub и удалённые репозитории | Удалённый репозиторий; создание на GitHub; `git remote add`, `git remote -v`; `git push -u`; `git clone`; `git fetch`, `git pull`; `origin/main`; вход в GitHub: токен и SSH-ключ | Опубликовать проект, отправить ветку, клонировать чужой репозиторий | 1–7 |
| 9. Командная работа | GitHub Flow; pull request и ревью; отклонённый `push`; расхождение веток; `pull.rebase` и `git pull --rebase`; `git rebase` (основы); `git stash`; `git cherry-pick` (обзор) | Синхронизироваться с товарищем по команде: stash, pull, разрешение, push | 1–8 |
| 10. Теги, релизы и итоговый проект | `git tag`, `git tag -a`, `git push --tags`; релизы на GitHub; алиасы `git config alias.*`; GitHub Pages; итоговый проект: свой сайт из курсов HTML/CSS/JS в репозитории на GitHub с историей, ветками, `.gitignore`, тегом `v1.0` | Полный цикл проекта от `git init` до тега и публикации | Все |

## Принципы курса

- Команды показываются так, как ученик их вводит в терминал. Перед командой в тексте урока - зачем она нужна, после - что вывел Git и как это читать.
- Используются современные команды: `git switch` и `git restore`, а `git checkout` упоминается как старая форма, которую ученик встретит в чужих инструкциях.
- Основная ветка - `main` (`git config --global init.defaultBranch main` в уроке 1).
- Сообщения коммитов - на английском, в повелительном наклонении, до 50 символов: `Add contact form`. Так принято в большинстве проектов и в GitHub.
- Опасные команды (`reset --hard`, `push --force`, `branch -D`) объясняются вместе с тем, когда их **нельзя** использовать.
- Вывод Git показывается на английском, как у ученика в терминале, с переводом и пояснением ключевых строк.
- Файлы в заданиях создаются командами `echo "..." > файл`, `echo "..." >> файл` и `cat > файл << 'EOF'`: в учебном терминале нет редактора.

## Практика на платформе

Задание в IDE - сценарий команд терминала. Платформа выполняет его в учебном симуляторе Git ([tools/gitsim/gitsim.js](tools/gitsim/gitsim.js)) и проверяет состояние: коммиты, ветки, файлы, удалённый репозиторий. Подробно - [platform/README.md](platform/README.md). Вне платформы те же команды выполняются в настоящем Git: часть 2 каждого урока - на своём компьютере.
