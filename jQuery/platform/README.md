# Задания IDE и тесты для JLearn (jQuery)

По одному файлу на урок: `lesson-01.json` … `lesson-10.json`. В каждом - задание для IDE в конце урока и тест на 12 вопросов. Формат теста (`test`) совпадает с курсами HTML и CSS. Проверка задания та же, что в курсе JavaScript (`JsTaskChecker`): код ученика **запускается** на странице задания, затем выполняются автоматические тесты. Единственное новое поле - `libraries`: платформа подключает jQuery к странице до кода ученика.

## Структура файла

```json
{
  "lesson": 1,
  "language": "ru",
  "lesson_title": "...",
  "task": {
    "title": "Название задания",
    "language": "javascript",
    "environment": "dom",
    "libraries": ["jquery"],
    "html": "<!DOCTYPE html>...",
    "description": "Условие для ученика",
    "starter_code": "Стартовый код в редакторе",
    "timeout_ms": 2000,
    "forbidden": ["var ", ".html(", "onclick"],
    "setup": "const courses = [...];",
    "tests": [
      {
        "name": "Что проверяется (видит ученик)",
        "check": "typeof studentName === \"string\"",
        "fail": "Сообщение, если тест не прошёл"
      }
    ],
    "hints": ["Подсказки"],
    "solution": "Эталонное решение (для преподавателя)",
    "wrong_solutions": [{"mistake": "...", "code": "..."}]
  },
  "test": {
    "pass_percent": 70,
    "questions": [ ... 12 вопросов ... ]
  }
}
```

## Как работает проверка (`JsTaskChecker`)

1. **Статическая часть.** Комментарии удаляются из кода, затем ищутся подстроки из `forbidden`. Найдена хотя бы одна - задание не засчитано, ученик видит, что именно запрещено.
2. **Библиотеки.** Для каждого имени из `libraries` платформа выполняет файл библиотеки на странице задания **до** `setup` и кода ученика. Во всех заданиях курса `"libraries": ["jquery"]` - это jQuery **4.1.0**, полная сборка (`jquery-4.1.0.min.js`, с эффектами и AJAX). После подключения в странице доступны `$` и `jQuery`.
3. **Запуск.** Код ученика выполняется в изолированной песочнице как обычный `<script>` (не модуль). Время ограничено `timeout_ms`: бесконечный цикл прерывается. Сеть, файловая система и `require` недоступны.
4. **Тесты.** Каждый `check` - выражение JavaScript, которое выполняется **в той же глобальной области**, что и код ученика, поэтому видит его переменные `let`/`const` и функции. Тест пройден, если выражение вернуло `true`. Если выражение бросило ошибку (например, переменной нет), тест не пройден.
5. **Входные данные (`setup`).** Необязательный код, который платформа выполняет **перед** кодом ученика: так задаются исходные данные, например `const score = 87;`. Ученик эти переменные не объявляет, а только использует. У отдельного теста может быть свой `setup` - тогда код ученика запускается заново в чистой песочнице с другими данными. Так одна программа проверяется на нескольких входах: граничные значения, пустая строка, ноль. В IDE ученик видит значения `setup` задачи в комментарии стартового кода.
6. **Результат.** Задание засчитано, когда пройдены все тесты. Ученику показываются `name` всех тестов с отметкой и `fail` для непройденных.

### Служебные переменные, доступные в `check`

| Переменная | Что содержит |
| --- | --- |
| `__logs` | Массив строк: каждый вызов `console.log(a, b)` даёт одну строку `"a b"` (объекты - через `JSON.stringify`) |
| `__code` | Исходный код ученика без комментариев |
| `__error` | Текст ошибки выполнения или `null`. В окружении `dom` сюда попадают и ошибки внутри обработчиков событий, которые произошли во время теста. Если ошибка есть, тесты всё равно выполняются - это позволяет засчитать часть тестов и показать сообщение |
| `document`, `window` | Только при `"environment": "dom"`: страница из поля `html`, код ученика подключён в конце `<body>` |

### Окружения

| `environment` | Уроки | Что есть в песочнице |
| --- | --- | --- |
| `dom` | 1–10 | Страница из поля `html` (jsdom), события можно вызывать в тестах через `dispatchEvent` или `.click()`; `localStorage` - в памяти. Каждый тест получает **свежую страницу**: `setup` → код ученика → `check`, поэтому клики одного теста не влияют на другой |

## Языки

| Папка | Язык |
| --- | --- |
| `platform/lesson-NN.json` | русский |
| `platform/uz/lesson-NN.json` | узбекский (латиница) |
| `platform/en/lesson-NN.json` | английский |

Имена переменных и функций, которые проверяют тесты, во всех языках одинаковые (английские, в `camelCase`). Переводятся условие, комментарии стартового кода, подсказки, сообщения `fail` и вопросы теста.

## Локальная проверка

```bash
node tools/check_platform_tasks.mjs
```

Скрипт для каждого файла проверяет: эталон проходит все тесты, каждое ошибочное решение не проходит хотя бы один, стартовый код не засчитывается, в тесте 12 вопросов с корректными индексами ответов. Нужны пакеты `jsdom` и `jquery@4.1.0` (`npm install` в папке `tools`).

## Особые случаи

- **Эффекты (урок 7).** В `setup` задания стоит `$.fx.off = true;`: анимации завершаются мгновенно, и тест сразу видит конечное состояние. Ученику это не нужно писать. Там же - заглушка `window.matchMedia` (в jsdom её нет), чтобы проверить учёт `prefers-reduced-motion`.
- **AJAX (урок 9).** Сети в песочнице нет. `setup` подменяет `$.getJSON` функцией, которая сразу возвращает выполненный или отклонённый `$.Deferred()` с тестовыми данными. Код ученика пишется так же, как для настоящего сервера. Проверки синхронные, поэтому в задании используются `.done` / `.fail` / `.always`: у выполненного `$.Deferred` они срабатывают сразу, а `await` - позже.
- **Формы (урок 8).** `setup` задаёт учебный «сервер» `sendApplication(data, onSuccess)` с задержкой; тесты вызывают `finishSending()`, чтобы проверить состояние до и после ответа.
- **Проверка одного файла:** `node tools/check_platform_tasks.mjs platform/uz/lesson-03.json`. Без аргумента каждый файл проверяется в отдельном процессе.

## Эталонные решения

В публичной версии курса поля `solution` и `wrong_solutions` удалены из файлов заданий - решайте задания сами. Скрипты проверки заданий из `tools/` рассчитаны на полную версию курса у преподавателя.
